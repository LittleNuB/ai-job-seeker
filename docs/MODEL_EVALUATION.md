# 智谱模型选型测评报告

日期：2026-05-07

## 测评背景

AI Job Copilot 核心功能（JD 深度解析、简历匹配分析）依赖 LLM 的结构化输出质量和分析深度。本次测评对比智谱开放平台 6 款模型，选取最适合本项目的模型。

## 测评方法

使用生产环境 JD 解析 prompt（含 hidden_needs、interview_focus 等深层分析要求），对同一份中文 JD 进行解析，从四个维度评估：

- **解析质量**：hidden_needs 洞察深度、interview_focus 可操作性、输出详实度
- **解析速度**：端到端延迟
- **解析成本**：有效输出 token 占比（推理 token 计费但用户不可见）
- **项目适配**：中文输出质量、JSON 格式遵从度

## 逐模型评价

### glm-4-flash（当前使用）
- 简单任务极快（1.6s），但在深度分析中**偷懒**——`team_context` 字段输出 `{"need_for_mature_contributor": true}` 布尔字典，完全没有完成分析任务
- **结论**：不适合生产级 JD 分析，排除

### glm-4.7-flashX
- 速度最快（31s），但 75% token 浪费于推理，有效输出仅 579 token，分析最浅
- **结论**：免费但质量不足，排除

### glm-5
- 分析深度好（273 字团队洞察），但输出**英文**，不适合中文求职场景
- **结论**：语言不匹配，排除

### glm-5.1
- 速度和质量居中，52% 推理浪费
- **结论**：无明显优势，排除

### glm-4.7
- 速度适中（40s），质量尚可，但 73% token 浪费于推理（1719/2329）
- **结论**：可用但成本效率低，作为备选

### GLM-4.5-AirX
- 输出最详实（2852 有效 token，是第二名的 3.2 倍）
- 零推理浪费（0%），所有 token 都是可用的分析内容
- 中文输出自然，JSON 格式稳定
- 深度分析中洞察最具体（118 字团队上下文 + 126 字岗位原因分析）
- 唯一缺点：深度分析延迟最高（81s），但考虑到输出质量可接受

## 最终选择：GLM-4.5-AirX

### 选择理由

1. **质量优先**：求职分析场景下，一份详实有洞察的报告比快 40s 更有价值。AirX 的有效输出量是推理模型的 3-5 倍
2. **零浪费**：推理模型 52-75% 的 token 用于不可见的"思考过程"但照常计费，AirX 无此浪费
3. **输出稳定**：简单和复杂任务均稳定输出 JSON，推理模型在匹配任务上 4/6 出现 JSON 解析失败
4. **中文原生**：glm-5 输出英文，AirX 中文输出自然流畅

### 权衡

- 延迟 81s vs 推理模型 30-55s，但考虑到异步分析场景，用户可以接受
- 如需进一步提速，可考虑调整 `max_tokens` 限制或 prompt 优化
