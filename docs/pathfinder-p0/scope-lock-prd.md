# 寻径星图 P0 Scope Lock 与 PRD

版本：P0 / Demo Lock

## 1. 产品判断

寻径星图短期应作为参赛 / 智联场景的新产品壳，技术上作为 AI Job Copilot 的新模块落地。

原因：

- 用户、叙事和入口不同于泛 AI 求职工具。
- 可以复用 AI Job Copilot 已有 JD 拆解、匹配解释、历史记录、导出、免责声明和 LLM 配置能力。
- P0 不改大架构，只新增一条 `/pathfinder` 闭环。

## 2. P0 目标

帮助传统工科、非 AI、非 CS 背景学生“小 C”，围绕固定任务：

> 工程企业知识库 AI 助手试航

基于固定开源项目：

> OpenDocuments

完成一次 AI 求职路径判断，并产出：

1. 航迹表
2. 作品集一页纸
3. Markdown 导出

## 3. P0 用户

唯一 Demo 用户：小 C。

画像：

- 传统工科硕士，3 个月内面临求职。
- 有工程资料理解、报告整理、用户调研或跨团队沟通经历。
- 有基础 Python / 数据处理能力，常用 AI 工具，对 RAG、知识库问答有初步理解。
- 缺少完整 AI 项目经历、算法研发经历和企业级系统交付证据。
- 目标是找到可试航的 AI 求职方向，而不是立即包装简历。

## 4. P0 路径锁定

只出现三条路径：

1. 行业 AI 应用产品助理：优先试航
2. 行业 AI 解决方案助理：适合探索
3. 算法工程 / 大模型研发：短期不建议

每条路径必须展示：

- JD 证据
- 小 C 背景证据
- OpenDocuments 证据
- 风险证据
- 下一步试航

## 5. P0 任务锁定

唯一任务：

> 基于 OpenDocuments，设计一次“工程企业知识库 AI 助手”的试航任务，包括项目理解、岗位连接、场景缺口、应用方案、作品延展和 AI 使用说明。

固定 6 问：

1. 项目理解：这个开源项目主要解决什么问题？输入和输出是什么？
2. 岗位连接：它能帮助你理解哪些 AI 产品或行业解决方案岗位工作？
3. 场景缺口：如果放到工程企业资料、规范、合同或施工方案管理场景中，还缺什么？
4. 应用方案：你会如何设计一个面向工程企业的 2 周试点 MVP？
5. 作品延展：如果把这次试航做成作品集草稿，你会包含哪些部分？
6. AI 使用说明：你是否使用 AI 辅助？AI 帮你做了什么？你如何筛选和修改？

## 6. P0 结果锁定

结果页必须包含：

1. 航迹表摘要
2. 作品集一页纸草稿
3. 指标表
4. 用户流程草图说明
5. 风险清单
6. 合规表达建议
7. 面试追问准备
8. Markdown 导出

## 7. P0 明确不做

- 不做能力认证
- 不做 offer 概率预测
- 不做企业筛选
- 不做简历自动包装
- 不做多开源项目推荐
- 不做真实 RAG 检索
- 不做复杂评分系统
- 不做职业测评
- 不做岗位海投建议
- 不做算法能力训练营
- 不做代码贡献路径规划
- 不暗示用户参与 OpenDocuments 官方贡献

## 8. 核心状态流

```text
INIT
  -> DEMO_LOADED
  -> PATHS_RENDERED
  -> PATH_SELECTED
  -> TRIAL_READY
  -> TRIAL_ANSWERED
  -> REPORT_GENERATED
  -> MARKDOWN_EXPORTED
```

异常状态只保留：

```text
DATA_MISSING
EXPORT_FAILED
```

## 9. 验收标准

Scope 验收：

- 只能出现小 C 一个 Demo 用户。
- 只能出现三条岗位路径。
- 只能出现 OpenDocuments 一个开源项目。
- 只能出现“工程企业知识库 AI 助手试航”一个任务。
- 只能导出 Markdown。
- 不出现 P1/P2 能力。

内容验收：

- “行业 AI 应用产品助理”必须是优先试航路径。
- “行业 AI 解决方案助理”必须是适合探索路径。
- “算法工程 / 大模型研发”必须明确标记为短期不建议。
- 不得暗示小 C 已具备算法工程能力。
- 不得暗示完成 Demo 等于获得岗位竞争优势认证。

导出验收：

- Markdown 必须包含 OpenDocuments 原项目能力、小 C 试航贡献、不可声称内容、开源来源与 License、免责声明。
