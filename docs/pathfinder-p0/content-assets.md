## 1. 小 C 背景样例

小 C，传统工科硕士，研究方向偏工程系统建模与设备数据分析。过去项目以实验设计、数据整理、工程报告、跨团队沟通为主，能读懂工艺、设备、运维类文档，也能用 Python 做基础数据处理与可视化。

当前求职周期约 3 个月，目标是从传统工科转向 AI 相关岗位，但暂未形成完整 AI 产品或研发项目经历。小 C 对大模型工具、知识库问答、RAG、提示词和评估方法有初步理解，短板是工程化开发深度、算法训练经验和线上项目经验。

当前更适合优先试航“行业 AI 应用产品助理”，用工科背景理解行业资料、拆解用户问题、设计 AI 助手使用场景和评估指标；可探索“行业 AI 解决方案助理”；短期不建议把算法工程或大模型研发作为主投方向。

小 C 匹配点：工科背景有利于理解工程企业场景，适合做需求翻译和方案辅助。

## 5. 固定 6 问小 C 作答样例

### 1. 项目理解

问题：这个开源项目主要解决什么问题？输入和输出是什么？

小 C 回答：OpenDocuments 主要解决企业资料分散、查找成本高、问答缺少来源依据的问题。输入可以是 GitHub、Notion、Google Drive、本地文件、网页等资料源；输出是基于文档检索生成的问答结果，并尽量展示引用来源，方便人工核验。

### 2. 岗位连接

问题：它能帮助你理解哪些 AI 产品或行业解决方案岗位工作？

小 C 回答：它能帮助我理解 AI 知识库、企业文档搜索、RAG 问答助手这类产品的工作内容，比如需求拆解、资料范围定义、问答样例设计、引用展示、失败兜底和验收指标。它也能帮助我理解解决方案岗位如何把一个开源技术参照转成企业 PoC 方案。

### 3. 场景缺口

问题：如果放到工程企业资料、规范、合同或施工方案管理场景中，还缺什么？

小 C 回答：还需要补工程企业自己的资料分级、权限规则、脱敏流程、文档更新机制、术语表、引用原文核验、合同类高风险提示，以及哪些问题不能由 AI 直接回答。尤其是合同、规范和施工方案，不能只追求回答速度，还要明确依据和人工复核节点。

### 4. 应用方案

问题：你会如何设计一个面向工程企业的 2 周试点 MVP？

小 C 回答：第 1 到 2 天确定试点范围，只选一类低风险资料，比如设备维护手册或内部操作规范。第 3 到 5 天整理脱敏文档、定义 20 个典型问题。第 6 到 9 天完成知识库导入、问答测试和引用核验。第 10 到 12 天记录失败案例、优化问题表达和兜底提示。第 13 到 14 天输出试点报告，包括命中情况、人工抽检、风险和下一步建议。

### 5. 作品延展

问题：如果把这次试航做成作品集草稿，你会包含哪些部分？

小 C 回答：我会包含背景问题、目标用户、MVP 范围、用户流程、样例问题、指标表、风险清单、Demo 截图或流程图、我的试航贡献，以及明确的边界说明：这是基于公开项目的产品拆解与试点设计，不是我参与原项目开发。

### 6. AI 使用说明

问题：你是否使用 AI 辅助？AI 帮你做了什么？你如何筛选和修改？

小 C 回答：我使用 AI 辅助整理公开项目信息、归纳岗位任务、生成初版问题清单和文案草稿。我会人工核对 GitHub 仓库、License 和 README 信息，删除过度承诺、能力认证、offer 预测、项目包装类表达，并把最终内容改成我能解释清楚的版本。

## 6. 作品集一页纸草稿

标题：工程企业知识库 AI 助手试航

作者：小 C

目标岗位：行业 AI 应用产品助理

问题背景：工程企业资料常分散在手册、SOP、项目文档和会议纪要中，新人或跨项目成员查找成本高，且难以判断答案来源。

方案概述：参考 OpenDocuments 的自托管 RAG 和文档搜索思路，设计一个面向工程资料的知识库问答助手，支持文档导入、自然语言提问、引用来源展示和反馈记录。

MVP 范围：文档上传 / 索引、问答、引用展示、人工反馈、无依据问题兜底。

评估指标：引用覆盖率、人工抽检通过率、无依据问题识别、典型问题完成时间、用户反馈记录率。

我的产出：用户问题清单、PRD 草稿、Demo 脚本、验收指标、风险清单、面试说明材料。

边界说明：本作品是基于公开项目信息的场景拆解与产品试航，不表述为本人参与原仓库开发。

## 8. 风险清单

| 风险 | 表现 | 建议处理 |
|---|---|---|
| 项目归属误解 | 把公开仓库说成个人开发成果 | 明确写“场景拆解与试航产出” |
| 过度承诺 | 说系统能稳定解决所有问答 | 改为“用于特定资料范围内辅助检索” |
| 数据安全 | 使用真实企业资料演示 | 使用脱敏或自建样例资料 |
| 幻觉答案 | 模型生成无依据内容 | 强制引用来源，无依据时提示无法确认 |

| 技术深度不足 | 被追问检索、切分、评估细节 | 准备基础解释和可验证指标 |

## 10. 面试追问准备

问：你为什么不主投算法岗？

答：我当前更强的是工程场景理解和产品化表达，算法研发还需要更长时间补代码、模型和实验积累，所以先从行业 AI 应用产品切入。

问：RAG 项目里你最关注什么？

答：我关注资料范围、引用来源、失败兜底和人工评估，因为企业知识库问答不能只看回答是否流畅。

问：你具体做了什么？

答：我做的是场景拆解、用户问题、MVP 范围、指标、风险和演示材料，不把公开仓库开发归到自己名下。

问：如果答案错了怎么办？

答：需要展示引用、允许反馈、记录问题类型，并对无依据问题给出无法确认提示，而不是继续生成看似确定的回答。
