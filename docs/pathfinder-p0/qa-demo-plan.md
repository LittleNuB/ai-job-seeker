# 寻径星图 P0 QA 与参赛演示方案

更新时间：2026-06-04

## 1. QA 结论

任务 6 QA / 参赛演示方案已通过，可以作为开发验收、上线前检查和参赛展示准备基线。

PM 口径补充：

- P0 主试航路径固定为“行业 AI 应用产品助理”。
- “行业 AI 解决方案助理”只作为适合探索路径展示，可在结果页作为下一步扩展建议。
- 后端保存 P0 主链路记录时，`selectedPathId` 应为 `industry-ai-product-assistant`。

## 2. P0 验收 Checklist

- [ ] 入口只走 `/pathfinder -> background -> recommendation -> trial -> result`
- [ ] Demo 用户只有小 C；开源项目只有 OpenDocuments；任务只有“工程企业知识库 AI 助手试航”
- [ ] 三条路径固定：行业 AI 应用产品助理为优先试航；解决方案助理为适合探索；算法 / 大模型研发为短期不建议
- [ ] 每条路径都有 JD 证据、小 C 背景证据、OpenDocuments 证据、风险证据、下一步试航
- [ ] 页面 4 明确区分“OpenDocuments 原项目能力”和“小 C 本次试航贡献”
- [ ] 固定 6 问全部使用 P0 文案，不出现 `q1-q6` 泛化问题
- [ ] 6 问未完成时，不生成完整航迹表，不允许完整 Markdown 导出
- [ ] Markdown 由前端纯函数生成，支持预览、复制、下载
- [ ] 后端只保存结构化结果和可选 `markdownSnapshot`，不生成 Markdown
- [ ] 页面、Mock 数据、导出内容全部通过禁用表达扫描和人工复核

## 3. 前端静态闭环 E2E 用例

| 用例 | 步骤 | 关键断言 |
|---|---|---|
| 主链路导出 | 打开 `/pathfinder`，进入小 C Demo，一键加载 Demo，查看推荐，开始试航，填入小 C 示例作答，生成结果，复制 / 下载 Markdown | 3 分钟内完成；结果页 8 个模块齐全；Markdown 包含来源、License、6 问作答、免责声明 |
| 未加载保护 | 直接访问 `/pathfinder/recommendation` | 提示需要先加载小 C 背景和样例 JD |

| 6 问缺项 | 只填写 5 问后尝试生成 / 预览 / 导出 | 显示缺项提示；不生成完整 Markdown |

| 禁用表达扫描 | 跑 `assertSafePathfinderCopy` 覆盖页面文案、Mock 数据、Markdown | 不命中禁用表达或同义风险表达 |
| 移动端 | 375px / 390px 宽度跑主链路 | 单列可读，无横向表格挤压，按钮和导出操作可点击 |

## 4. 后端记录保存 API 测试用例

- `POST /api/pathfinder/records`：创建记录，断言 `analysis_records.type = "pathfinder"`，`input_file_url = null`，`match_score = null`，`input_text` 为 P0 输入 JSON。
- `GET /api/pathfinder/records/{record_id}`：只能读取本人 `user_id + id + type = "pathfinder"` 的记录；跨用户返回 404 / 403。
- `PATCH /api/pathfinder/records/{record_id}/trial-answers`：只接受 6 个固定 id：`project_understanding`、`role_connection`、`scenario_gap`、`application_solution`、`portfolio_extension`、`ai_usage_explanation`。
- `PUT /api/pathfinder/records/{record_id}/result`：保存 `trialAnswers`、`report`、可选 `markdownSnapshot`；后端不改写 Markdown。
- `DELETE /api/pathfinder/records/{record_id}`：删除本人 Pathfinder 记录，不影响其他类型历史记录。
- 负向测试：P0 主链路保存时拒绝 `selectedPathId` 非 `industry-ai-product-assistant` 的结果；拒绝后端返回匹配分、胜任分、企业推荐、自动简历建议等字段。
- Schema 测试：不新增 `pathfinder_records` 表，不要求迁移；复用现有 `analysis_records` 字段。

## 5. 反包装文案检查清单

- 项目归属：必须写“基于 OpenDocuments 做产品拆解 / 试航”，不得写成小 C 开发或参与原仓库。
- 个人贡献：只写“试航方案、问题清单、指标表、风险清单、演示材料”，不写成企业级系统开发成果。
- 岗位结论：写“优先试航该路径”，不写“已适配 / 已胜任”。
- 求职结果：写“用于作品集和面试表达准备”，不写录用预测、概率、保证类表达。
- 技术能力：写“理解 RAG 产品流程”，不写研发能力背书。
- Demo 范围：写“2 周试点 MVP 设计”，不写可直接上线或替代专业审核。
- OpenDocuments：必须标注 GitHub 来源和 MIT License；原项目能力与小 C 试航贡献分栏呈现。

## 6. Markdown 导出检查清单

- [ ] 候选人背景：传统工科硕士、资料理解、报告整理、基础 Python / RAG 理解、短板清楚
- [ ] 星图路径结论：产品助理优先，解决方案助理可探索，算法 / 大模型研发短期不建议
- [ ] 样例 JD 说明：仅用于 P0 Demo 和样本趋势参考
- [ ] 开源来源与 License：OpenDocuments、GitHub URL、MIT
- [ ] OpenDocuments 原项目能力：多来源接入、文档搜索、RAG 问答、引用来源、Web UI / CLI / MCP
- [ ] 小 C 试航贡献：6 问作答、MVP、指标、风险、作品集草稿
- [ ] 不可声称内容：不能说本人开发原项目、不能说代表岗位结果、不能说 AI 替代专业审核
- [ ] 固定 6 问完整导出：问题、小 C 回答、证据来源、边界提示
- [ ] 免责声明：这是试航记录，不是能力背书或官方记录
- [ ] 缺任意一问时，只能导出草稿 / 缺项状态，不能导出完整 Markdown

## 10. 现场提问预案

| 问题 | 回答 |
|---|---|
| 为什么小 C 不优先算法岗？ | 小 C 当前强项是工程语境理解、资料整理和产品表达，算法岗需要更强代码、模型实验和工程证据，所以短期不作为主线。 |
| 为什么选 OpenDocuments？ | 它对应企业资料分散、文档问答、引用来源这些真实场景，适合拆成 AI 知识库产品任务。 |
| 小 C 到底做了什么？ | 做场景拆解、用户问题、2 周 MVP、指标、风险和展示材料；不声称参与原仓库开发。 |
| 这和简历包装有什么区别？ | P0 强制写清来源、边界和不可声称内容，并阻断缺项导出，目标是可解释的试航记录。 |
| 后端为什么不生成 Markdown？ | P0 决策是前端纯函数即时导出，后端只保存结构化结果和可选快照，避免模板双写和文案不一致。 |
| 6 问为什么必须完整？ | 6 问覆盖项目理解、岗位连接、场景缺口、方案、作品延展和 AI 使用说明，缺任何一项都会破坏可追溯性。 |

## 11. 上线前风险清单

| 风险 | 级别 | 处理 |
|---|---|---|
| 页面或导出出现禁用表达 | 高 | 正则扫描 + 人工逐页复核 + 导出样本复核 |
| OpenDocuments 原能力被写成小 C 贡献 | 高 | 页面分区、Markdown 分节、截图检查 |
| 6 问未完成仍可导出完整 Markdown | 高 | E2E 阻断用例必须通过 |
| 后端误加 Markdown 模板或评分字段 | 中 | API contract 测试锁定字段 |
| 演示超过 3 分钟 | 中 | 使用示例作答按钮，备用截图兜底 |
| 移动端表格挤压 | 中 | 指标表移动端改卡片或横向可控滚动 |
| 文案把样例 JD 写成真实岗位判断 | 中 | 样例 JD 说明必须出现在页面和导出 |
| 现场网络 / 服务异常 | 中 | 准备本地静态链路、Markdown 样本和备用截图 |
