## 1. 文档目的与边界

本文档用于固化“寻径星图 P1 UI / 视觉升级方案”，目标是把当前能跑通的 P0 Demo 页面升级为：

> 精密、克制、证据驱动的求职试航工作台。

本文档只定义 P1 UI 设计方向、页面结构、组件规格、状态呈现和视觉验收标准，不修改 P0 Scope Lock，不新增 P0 / P1 业务能力。

P0 主线保持不变：

- 唯一 Demo 用户：小 C
- 三条岗位路径：
  - 行业 AI 应用产品助理：优先试航
  - 行业 AI 解决方案助理：适合探索
  - 算法工程 / 大模型研发：短期不建议
- 唯一开源参考项目：OpenDocuments
- 唯一试航任务：工程企业知识库 AI 助手试航
- 唯一导出格式：Markdown

P1 UI 升级只改善：

- 可读性
- 专业感
- 信息层级
- 展示冲击力
- 反包装识别度
- 3 分钟演示效率

P1 UI 升级不新增：

- 岗位推荐能力
- 能力认证
- offer 概率预测
- 企业筛选
- 简历包装
- 多开源项目智能推荐
- 真实 RAG 检索
- 复杂评分系统
- OpenDocuments 官方贡献暗示

## 2. 当前 UI 问题诊断

以下诊断基于 P0 已完成的静态闭环和文档基线，重点指出最影响观感、可信度和演示效率的问题。

### 2.1 入口页

当前问题：

- 固定 Demo 边界需要更强首屏可见性。用户应在 5 秒内知道这不是开放式 JD 推荐器，也不是简历包装工具。
- 输入 / 输出预览还需要更像“任务工作台”的结构，而不是普通流程说明。
- 反包装声明如果只是普通说明文字，演示时不够醒目。
- P0 主线中的“小 C + 样例 JD + OpenDocuments + 工程企业知识库 AI 助手 + Markdown”需要形成一眼可扫的链路。

### 2.2 背景页

当前问题：

- 小 C 的优势、短板、目标需要更明确对照，尤其要解释为什么短期不能主投算法岗。
- 3 条样例 JD 如果只是并列卡片，扫描效率不足，用户不容易在首屏看出三条路径的差异。
- “样例 JD 不是具体岗位判断”的提示需要更靠近 JD 卡片，而不是只放在页面说明中。
- 小 C 的技术基础应突出“基础 Python / 数据处理、常用 AI 工具、RAG / 知识库问答初步理解”，避免给人“基础前端”错位印象。

### 2.3 推荐页

当前问题：

- 三条路径必须并列展示，但视觉权重应明显突出主推荐路径，否则 5 秒内无法看懂为什么主推“行业 AI 应用产品助理”。
- 证据链需要从普通文本升级为结构化证据矩阵，减少用户逐段阅读成本。
- “算法工程 / 大模型研发：短期不建议”需要被设计为理性边界，而不是失败或否定小 C。
- 每条路径的“下一步试航”需要保持可见，但只有主路径拥有强 CTA。

### 2.4 试航页

当前问题：

- OpenDocuments 原项目能力与小 C 本次试航作答必须更强视觉分区，避免原项目能力被误读为小 C 产出。
- OpenDocuments 来源与 License 需要成为来源面板的稳定元素，不应只出现在导出或结果页。
- 固定 6 问与结果页模块之间的映射需要可视化，否则用户不理解为什么缺一问会阻断完整导出。
- 第 6 问 AI 使用说明为空时的阻断状态应具备更强的反包装解释，而不是普通表单校验。
- “填入演示用小 C 作答，可继续编辑”应明确是 Demo 辅助动作，不应像自动生成包装内容。

### 2.5 结果页

当前问题：

- 结果页首屏需要先展示追溯链，而不是直接进入多个结果模块。
- “可追溯作品集起点”与“能力认证”之间的区别需要更强视觉提示。
- 8 个结果区块如果仅纵向堆叠，演示时不容易快速定位 Markdown 导出、不可声称内容和反包装检查。
- 缺项状态和完整状态需要有明显差异，尤其要能截图展示“不能导出完整 Markdown”的原因。
- Markdown 导出入口应首屏或近首屏可见，避免演示过程中滚动寻找。

## 3. P1 UI 总体方向

### 3.1 设计关键词

- 精密：信息结构清楚，证据、来源、贡献边界都有稳定位置。
- 克制：不使用营销型首页、大面积装饰渐变或证书式视觉。
- 证据驱动：每个路径结论都能回到 JD、小 C 背景、OpenDocuments 和风险证据。
- 反包装：所有结果都明确“可说什么 / 不可声称什么”。
- 可演示：3 分钟内完成主线讲解，关键判断首屏可见。

### 3.2 视觉气质

建议采用“求职试航工作台”气质：

- 背景干净，信息密度高但不拥挤。
- 卡片更像工作流面板，而不是营销卡片。
- 状态标签清晰但不夸张。
- 风险与边界提示有辨识度，但不制造恐吓感。
- 结果页像一份可审阅的记录，而不是证书、排行榜或简历生成器。

避免：

- 星空科技感 landing page
- 大面积装饰性渐变
- 营销型首页
- 简历包装工具视觉
- 能力认证证书感
- 分数排行榜感
- 企业筛选后台感

### 3.3 信息密度原则

- 每页首屏只回答一个问题。
- 主路径优先出现，对照路径次级呈现。
- 长文本默认摘要化，详情通过折叠、抽屉或次级层展示。
- 证据内容用短句，不用大段叙述。
- 表格只用于真正需要比较的内容；移动端改卡片。

### 3.4 反包装识别原则

反包装信息必须具备固定视觉模式：

- 来源类信息使用“来源 / License / 原项目能力”样式。
- 小 C 产出使用“本次试航作答 / 小 C 新增”样式。
- 不可声称内容使用警示但克制的边界提示样式。
- 缺项阻断使用“无法导出完整 Markdown”的明确状态，而不是泛化错误提示。

### 3.5 3 分钟演示优先原则

每页必须支持一句话讲解：

- 入口页：这是固定 Demo，不是简历包装工具。
- 背景页：小 C 的优势适合产品试航，短期不适合算法主投。
- 推荐页：主推行业 AI 应用产品助理，因为证据链最完整。
- 试航页：左侧是来源，右侧是小 C 作答。
- 结果页：这是作品集起点，不是能力认证。

## 4. 视觉系统建议

以下为设计 token 草案，只定义方向，不要求前端立即写成正式 token 系统。

### 4.1 色彩方向

基础色：

- 页面背景：接近白色的冷灰，避免纯白长页疲劳。
- 主文本：深灰黑，用于标题和核心结论。
- 次文本：中性灰，用于解释、来源、限制。
- 分割线 / 边框：浅灰，用于结构分区。

功能色：

- 主推荐 / 优先试航：稳重蓝绿色或深青色，表达可行动但不夸张。
- 适合探索：中性蓝或灰蓝，表达可继续观察。
- 短期不建议：琥珀 / 暖灰，表达风险边界，不用危险红大面积渲染。
- 风险 / 不可声称：低饱和橙红，仅用于边界提示、阻断和禁用表达。
- 来源 / License：灰蓝或石墨色，和小 C 产出区明显区分。

禁用视觉：

- 大面积紫蓝渐变
- 星空背景
- 排名红绿灯式强刺激配色
- 证书金色
- 招聘后台式高饱和数据看板色

### 4.2 字体层级

建议层级：

- 页面 H1：用于每页核心问题，不超过两行。
- 页面说明：紧跟 H1，说明边界或任务。
- 区块标题：用于模块识别，短语化。
- 卡片标题：路径名、结果模块名、问题名。
- 证据标签：JD 证据、小 C 背景证据、OpenDocuments 证据、风险证据。
- 来源 / License / 免责声明：小字号但不能低到不可读。

原则：

- 不使用超大 hero 字号。
- 卡片内标题保持紧凑。
- 长句换行后仍保持清晰行距。
- 移动端不按视口缩放字号，避免文字跳动。

### 4.3 间距 / 卡片 / 边框

建议：

- 页面主体使用居中最大宽度，桌面端保留足够边距。
- 卡片圆角控制在 8px 以内。
- 卡片不嵌套卡片；复杂内容用分区、边框或背景色区分。
- OpenDocuments 来源区和小 C 作答区使用不同边框色和标题栏，形成稳定识别。
- 结果页每个结果模块使用清晰区块，不做漂浮装饰卡片堆叠。

### 4.4 状态标签

固定标签：

- `固定 Demo`
- `优先试航`
- `适合探索`
- `短期不建议`
- `来源：OpenDocuments 公开能力`
- `小 C 本次试航新增`
- `缺项`
- `完整可导出`
- `不可声称`

标签原则：

- 不新增“高分”“通过”“认证”“胜任”等状态。
- 主路径标签视觉最强，但不使用分数或排名。
- 风险标签用于解释边界，不用于评价小 C 能力。

### 4.5 按钮层级

主按钮：

- 进入小 C Demo
- 查看星图推荐
- 开始 OpenDocuments 试航
- 生成航迹表
- 复制 Markdown
- 下载 Markdown

次级按钮：

- 返回修改
- 预览 Markdown
- 填入演示用小 C 作答，可继续编辑

禁用按钮：

- 第 6 问为空时，生成 / 完整导出按钮禁用，并在按钮旁显示阻断原因。

按钮原则：

- 一页只保留一个主 CTA。
- 不使用“立即提升”“生成简历”“获得认证”等营销或越界文案。
- 移动端按钮不可换行挤压，必要时上下堆叠。

### 4.6 风险 / 边界提示样式

建议三类提示：

- 信息提示：说明样例 JD、Demo 范围、来源。
- 边界提示：说明原项目能力与小 C 试航贡献的差异。
- 阻断提示：说明缺项导致不能导出完整 Markdown。

阻断提示必须包含：

- 缺少哪个问题
- 影响哪个结果模块
- 为什么会影响追溯链
- 如何恢复完整导出

### 4.7 Markdown / 来源信息样式

Markdown 预览：

- 使用等宽字体或文档预览样式。
- 预览顶部显示“完整 / 缺项”状态。
- 导出按钮与预览内容保持相邻。
- 缺项状态下允许查看草稿，但不能展示为完整导出。

来源信息：

- OpenDocuments 名称、GitHub 来源、MIT License 固定在来源面板和结果页追溯链中。
- 来源信息应视觉上靠近原项目能力，而不是靠近小 C 作答。

## 5. 页面级改造方案

### 5.1 入口页

页面目标：

- 5 秒内让用户知道这是固定 Demo，不是简历包装工具。

首屏必须出现的信息：

- 标题：寻径星图：小 C 的工程企业知识库 AI 助手试航
- 固定 Demo 边界：1 个用户、3 条路径、1 个项目、1 个任务、Markdown 导出
- 反包装声明：不做能力认证、企业推荐、录用预测或简历包装
- 输入 / 输出预览
- 主 CTA：进入小 C Demo

主要布局建议：

- 顶部保留简洁步骤进度。
- 主体采用两栏：左侧为 Demo 主线和反包装声明，右侧为输入 / 输出预览。
- 输入预览用紧凑链路展示：小 C 背景、样例 JD、OpenDocuments。
- 输出预览展示：路径结论、6 问试航、航迹表、Markdown。
- 反包装声明使用边界提示组件，位置靠近主 CTA。

关键组件：

- `StepProgress`
- `DemoBoundaryPanel`
- `InputOutputPreview`
- `AntiPackagingNotice`
- `PrimaryCTA`

P0 polish 可微调项：

- 强化入口页边界文案。
- 把“这不是简历包装工具”放入首屏。
- 输入 / 输出预览可用现有内容做更清晰排版。

P1 必做项：

- 建立固定 Demo 边界面板。
- 建立反包装声明的统一视觉样式。
- 首屏同时露出输入链路和输出资产。

P2 可平台化项：

- 多试航包入口，但只能是已审核试航包选择，不是智能推荐入口。

### 5.2 背景页

页面目标：

- 快速理解小 C 的优势、短板和为什么不能短期主投算法岗。

首屏必须出现的信息：

- 小 C 背景摘要
- 优势 / 短板 / 目标对照
- 3 条样例 JD 卡
- 样例 JD 说明
- 主 CTA：查看星图推荐

主要布局建议：

- 桌面端左侧为小 C 背景对照面板，右侧为 3 条样例 JD。
- 小 C 背景分为“优势 / 短板 / 目标 / 当前技术基础”四块。
- 技术基础固定展示：
  - 基础 Python / 数据处理
  - 常用 AI 工具使用
  - 对 RAG、知识库问答有初步理解
- 3 条 JD 卡使用不同状态标签，但不使用分数。
- 算法工程 / 大模型研发卡片应展示“短期不建议”的证据入口，避免用户误以为只是排序靠后。

关键组件：

- `ProfileContrastPanel`
- `TechnicalBaselineList`
- `SampleJDCard`
- `SampleJDDisclaimer`
- `DemoLoadButton`

P0 polish 可微调项：

- 优势、短板、目标文案分区。
- 样例 JD 提示靠近 JD 卡片。
- “一键加载 Demo”文案保留演示属性。

P1 必做项：

- 小 C 背景对照布局。
- 3 条 JD 扫描效率优化。
- 算法岗短期不建议的视觉边界明确化。

P2 可平台化项：

- TrialPackage 中的候选人背景模板展示，但仍不开放任意 JD 粘贴作为 P1 UI 目标。

### 5.3 推荐页

页面目标：

- 5 秒内看懂为什么主推“行业 AI 应用产品助理”。

首屏必须出现的信息：

- 推荐结论：行业 AI 应用产品助理：优先试航
- 两个对照路径：适合探索、短期不建议
- 主路径四类证据摘要
- 主 CTA：开始 OpenDocuments 试航

主要布局建议：

- 主推荐路径使用更宽或更高权重卡片，放在左侧或顶部。
- 两个对照路径使用较轻量卡片，放在右侧或下方。
- 三条路径状态保持固定：
  - 行业 AI 应用产品助理：优先试航
  - 行业 AI 解决方案助理：适合探索
  - 算法工程 / 大模型研发：短期不建议
- 每条路径都展示五个部分：
  - JD 证据
  - 小 C 背景证据
  - OpenDocuments 证据
  - 风险证据
  - 下一步试航
- 证据链建议采用矩阵式短句，而不是长段落。

关键组件：

- `PrimaryPathCard`
- `ComparisonPathCard`
- `EvidenceChain`
- `RiskEvidence`
- `NextTrialAction`

P0 polish 可微调项：

- 主推荐结论放到页面顶部。
- 三条路径文案保持 P0 polish 最终稿。
- 用标签强化“优先试航 / 适合探索 / 短期不建议”。

P1 必做项：

- 主路径与对照路径的视觉权重区分。
- 四类证据结构化展示。
- 主路径 CTA 唯一强操作，对照路径只展示下一步说明。

P2 可平台化项：

- 多 TrialPackage 下的路径卡复用，但不能演变成岗位推荐排序器。

### 5.4 试航页

页面目标：

- 5 秒内看懂左侧是 OpenDocuments 原项目能力，右侧是小 C 本次试航作答。

首屏必须出现的信息：

- OpenDocuments 来源与 License
- OpenDocuments 原项目能力
- 小 C 本次试航作答区
- 贡献边界提示
- 固定 6 问进度
- 示例作答按钮：填入演示用小 C 作答，可继续编辑

主要布局建议：

- 桌面端采用左右分区：
  - 左侧：OpenDocuments 来源面板，只读
  - 右侧：小 C 6 问作答，可编辑
- 来源面板固定展示：
  - 项目名称：OpenDocuments
  - 来源：GitHub
  - License：MIT
  - 公开能力：
    - 多来源文档接入
    - AI 文档搜索
    - RAG 问答
    - 引用来源展示
    - Web UI / CLI / MCP 等公开能力
- 6 问每问展示“影响结果模块”：
  - 项目理解：来源说明、原项目能力理解、项目归属边界
  - 岗位连接：路径结论、JD 证据、小 C 背景证据
  - 场景缺口：风险清单、工程企业场景边界、不可声称内容
  - 应用方案：2 周 MVP、用户流程草图、指标表
  - 作品延展：作品集一页纸草稿、面试解释材料
  - AI 使用说明：免责声明、反包装检查、完整 Markdown 导出
- 第 6 问为空时，阻断提示必须直接显示在按钮区附近。

关键组件：

- `OpenDocumentsSourcePanel`
- `LicenseBadge`
- `SourceCapabilityList`

P0 polish 可微调项：

- 强化左右分区标题。
- 第 6 问为空时按钮禁用并展示 P0 polish 阻断文案。
- 示例作答按钮使用“演示用、可继续编辑”表达。

P1 必做项：

- OpenDocuments 来源与 License 常驻。
- 原项目能力与小 C 试航贡献视觉强分区。
- 6 问与结果模块映射可见。
- 缺项阻断状态可截图说明。

P2 可平台化项：

- TrialPackage 中的来源面板和固定问题映射可配置，但配置发布前必须经过 Scope Guard。

### 5.5 结果页

页面目标：

- 5 秒内看懂这是“可追溯作品集起点”，不是能力认证。

首屏必须出现的信息：

- 追溯链：
  - 样例 JD + 小 C 背景 + OpenDocuments 原项目能力 -> 6 问试航 -> 航迹表 / 作品集草稿 / Markdown
- 完成状态或缺项状态
- 反包装检查摘要
- Markdown 导出入口
- 免责声明入口或摘要

主要布局建议：

- 顶部设置结果总览条，包含追溯链、状态和导出操作。
- 完整状态显示“完整可导出”，缺项状态显示“缺项，不能导出完整 Markdown”。
- 反包装检查摘要靠近 Markdown 导出区，列出：
  - 来源已标注
  - License 已标注
  - 原项目能力与小 C 试航贡献已分区
  - 不可声称内容已展示
  - AI 使用说明已填写
- 结果区按固定 8 模块展示：
  1. 航迹表摘要
  2. 作品集一页纸草稿
  3. 指标表
  4. 用户流程草图说明
  5. 风险清单
  6. 合规表达建议
  7. 面试追问准备
  8. Markdown 导出
- 不可声称内容和免责声明要有稳定视觉位置，不能被放到页面末尾弱化。

关键组件：

- `TraceChain`
- `ResultStatusBanner`
- `AntiPackagingSummary`
- `TrailSummary`
- `PortfolioOnePagerCard`
- `MetricTable`
- `FlowSketchText`
- `RiskTable`

- `MarkdownExportPanel`
- `DisclaimerPanel`

P0 polish 可微调项：

- 首屏补充追溯链文案。
- Markdown 导出区展示完整 / 缺项状态。
- 不可声称内容提示更靠前。

P1 必做项：

- 结果追溯链组件化。
- 反包装检查摘要组件化。

## 6. 组件设计清单

### 6.1 航线进度条 / StepProgress

用途：

- 展示 5 页闭环进度。
- 强化线性试航，不引导跳到未完成能力。

要求：

- 桌面端展示 5 步名称。
- 移动端展示当前步数和当前页面名。
- 不提供跳转到未定义 P1/P2 能力的入口。

### 6.2 主路径推荐卡

用途：

- 承载“行业 AI 应用产品助理：优先试航”。

要求：

- 视觉权重大于对照路径卡。
- 首屏展示四类证据摘要和主 CTA。
- 不出现分数、排名、胜任标签。

### 6.3 对照路径卡

用途：

- 展示“行业 AI 解决方案助理：适合探索”和“算法工程 / 大模型研发：短期不建议”。

要求：

- 视觉上次于主路径。
- 仍保留 JD 证据、小 C 背景证据、OpenDocuments 证据、风险证据、下一步试航。
- 不提供强 CTA。

### 6.4 证据链组件

用途：

- 统一展示四类证据和下一步试航。

字段：

- JD 证据
- 小 C 背景证据
- OpenDocuments 证据
- 风险证据
- 下一步试航

要求：

- 每类证据使用稳定图标或标签。
- 风险证据必须可见，不能折叠到不可发现位置。

### 6.5 边界提示组件

用途：

- 展示 Demo 边界、原项目归属、不可声称内容和免责声明。

要求：

- 和普通帮助文本视觉区分。
- 语气克制，不制造恐吓。
- 可复用在入口、试航、结果页。

### 6.6 OpenDocuments 来源面板

用途：

- 展示 OpenDocuments 来源、License 和公开能力。

固定内容：

- OpenDocuments
- GitHub 来源
- MIT License
- 多来源文档接入
- AI 文档搜索
- RAG 问答
- 引用来源展示
- Web UI / CLI / MCP 等公开能力

要求：

- 只读。
- 明确标注“来源：OpenDocuments 公开能力”。
- 不能出现“官方贡献”“公开 issue”作为主流程内容。

### 6.7 6 问表单状态组件

用途：

- 展示固定 6 问完成度和每问影响的结果模块。

要求：

- 每问有完成 / 缺项状态。
- 第 6 问 AI 使用说明单独强调。
- 示例作答按钮标注“演示用，可继续编辑”。

### 6.8 缺项阻断提示

用途：

- 在 6 问缺项或第 6 问为空时阻断完整 Markdown 导出。

要求：

- 清楚说明不能导出完整 Markdown。
- 显示缺少的问题。
- 显示影响的追溯链或结果模块。
- 提供返回补充动作。

### 6.9 结果追溯链

用途：

- 结果页首屏解释输出如何产生。

固定链路：

> 样例 JD + 小 C 背景 + OpenDocuments 原项目能力 -> 6 问试航 -> 航迹表 / 作品集草稿 / Markdown

要求：

- 桌面端可横向展示。
- 移动端改为纵向步骤。
- 不展示评分或算法推荐过程。

### 6.10 作品集草稿卡

用途：

- 展示作品集一页纸草稿。

要求：

- 标注“草稿 / 试航材料”。
- 显示边界说明。
- 不使用证书、奖章、通过类视觉。

### 6.11 风险表 / 指标表

用途：

- 展示指标设计和风险清单。

要求：

- 桌面端可使用表格。
- 移动端转为卡片列表。
- 风险表不评价小 C 能力，只描述试航边界和处理方式。

### 6.12 Markdown 预览与导出区

用途：

- 预览、复制、下载 Markdown。

要求：

- 显示完整 / 缺项状态。
- 完整导出需要 6 问全部完成，尤其第 6 问不能为空。
- 预览内容包含来源、License、原项目能力、小 C 试航贡献、不可声称内容和免责声明。

### 6.13 反包装检查摘要

用途：

- 结果页展示导出前的边界检查感。

建议检查项：

- OpenDocuments 来源已标注
- License 已标注
- 原项目能力与小 C 试航贡献已分区
- 不可声称内容已展示
- 第 6 问 AI 使用说明已填写
- 未出现能力认证、offer 概率、官方贡献暗示

要求：

- 不是评分系统。
- 不显示通过分数或等级。
- 缺项时明确阻断原因。

## 7. 响应式设计要求

### 7.1 1440px 桌面端

布局要求：

- 页面主体可使用双栏或主次栏。
- 推荐页主路径卡可占更大宽度，对照路径放右侧或下方。
- 试航页左右分区同时可见。
- 结果页顶部追溯链、状态和导出入口同时可见。

验收点：

- 首屏不显得空泛。
- 关键信息不被折叠。
- 表格可读，不需要横向滚动。

### 7.2 1024px 窄屏

布局要求：

- 双栏可保留，但需要降低列间距和卡片密度。
- 推荐页可改为主路径在上、两个对照路径并列在下。
- 试航页来源面板可变为上方摘要，6 问作答在下方。
- 结果页导出入口固定在顶部区或首屏底部。

验收点：

- 按钮不换行挤压。
- 标签不遮挡标题。
- 证据链不被压缩成难读小字。

### 7.3 390px 移动端

布局要求：

- 全流程单列。
- StepProgress 显示为“当前步 / 总步数 + 页面名”。
- 推荐页主路径必须先出现，然后才是两个对照路径。
- 试航页先展示 OpenDocuments 来源摘要，再展示小 C 作答区。
- 表格全部转为卡片列表。
- Markdown 导出入口在结果页首屏可见。

验收点：

- 文案不遮挡。
- 主按钮不横向溢出。
- 结果页仍能看到追溯链和导出入口。

### 7.4 375px 移动端

布局要求：

- 进一步减少并列元素，所有卡片单列。
- 状态标签允许换到标题下方。
- 长按钮使用上下堆叠。
- Markdown 操作按钮可分行展示。

验收点：

- 无横向页面溢出。
- 长路径名不撑破卡片。
- 风险表 / 指标表卡片仍可读。
- 缺项阻断提示完整可见。

## 8. 3 分钟演示视觉验收标准

入口页：

- 5 秒内知道这是固定 Demo。
- 5 秒内知道它不是简历包装工具。
- 首屏能看到固定输入和输出预览。
- 反包装声明不需要滚动即可看到。

背景页：

- 5 秒内看懂小 C 的优势、短板和目标。
- 5 秒内知道 3 条 JD 是样例 JD，不是具体岗位判断。
- 能解释为什么短期不能主投算法岗。

推荐页：

- 5 秒内知道主推“行业 AI 应用产品助理”。
- 主路径视觉权重大于另外两条。
- 三条路径状态清楚：
  - 行业 AI 应用产品助理：优先试航
  - 行业 AI 解决方案助理：适合探索
  - 算法工程 / 大模型研发：短期不建议
- 主路径能看到 JD 证据、小 C 背景证据、OpenDocuments 证据和风险证据。

试航页：

- 5 秒内知道左侧是来源，右侧是作答。
- OpenDocuments 来源与 MIT License 可见。
- 小 C 试航贡献边界可见。
- 固定 6 问与结果模块映射可见。
- 第 6 问为空时，阻断状态能清楚展示不能导出完整 Markdown。

结果页：

- 5 秒内知道这是作品集起点，不是能力认证。
- 追溯链首屏可见。
- 完成状态或缺项状态可见。
- 反包装检查摘要可见。
- Markdown 复制 / 下载入口可见。
- 不可声称内容和免责声明可被快速定位。

缺项阻断截图：

- 截图中必须能看到缺少的问题。
- 截图中必须能看到“不能导出完整 Markdown”。
- 截图中必须能看到影响的结果模块或追溯链。
- 截图中不能出现评分、认证或录用预测表达。

## 9. 给前端的实现注意事项

### 9.1 P0 polish 可以先做

以下改动属于 P0 polish，可以在不等待 P1 大改的情况下先做：

- 入口页首屏强化固定 Demo 边界文案。
- 背景页把小 C 优势、短板、目标分区展示。
- 推荐页把主推荐结论前置。
- 试航页强化“OpenDocuments 原项目能力”和“小 C 本次试航作答”的标题与边界提示。
- 第 6 问为空时，使用 P0 polish 已锁定阻断文案。
- 结果页首屏补充追溯链文案。
- Markdown 导出区显示完整 / 缺项状态。
- 禁止表达扫描继续覆盖页面文案、Mock 数据和 Markdown。

### 9.2 P1 UI 大改再做

以下改动属于 P1 UI 结构升级，建议在 P1 UI 统一改版时做：

- 全局视觉系统和基础 token 收敛。
- 主路径推荐卡、对照路径卡的视觉权重重做。
- 证据链组件化。
- OpenDocuments 来源面板组件化。
- 6 问与结果模块映射组件化。
- 结果追溯链组件化。
- 反包装检查摘要组件化。
- 表格移动端卡片化。
- Markdown 预览与导出区重构为稳定模块。

### 9.3 不要求前端新增 P1 业务模块

本 UI brief 不要求前端新增：

- 新岗位推荐
- 新路径选择器
- 企业筛选入口
- 多项目推荐入口
- 评分或概率字段
- 认证结果
- 简历生成器
- 真实 RAG 检索
- OpenDocuments 仓库实时抓取

若后续进入 P1 产品化对象建设，应以 `p1-product-roadmap.md` 中的 TrialPackage、TrailRecord、AntiPackagingCheck 规划为准，不能反向扩大 P0 Demo。

## 10. 明确不做清单

P1 UI 设计不得引导以下越界方向：

- 不做能力认证
- 不做岗位胜任认证
- 不做 offer 概率预测
- 不做录用概率、上岸概率或求职结果承诺
- 不做企业筛选
- 不做企业推荐或精准内推
- 不做简历包装
- 不做简历自动优化
- 不做自动投递
- 不做多开源项目智能推荐
- 不做真实 RAG 检索
- 不做复杂评分系统
- 不做分数排行榜
- 不做算法工程速成
- 不做大模型研发训练路径
- 不暗示小 C 参与 OpenDocuments 官方贡献
- 不暗示 OpenDocuments 原项目能力属于小 C 个人产出
- 不暗示完成试航等于具备岗位录用优势
- 不把结果页做成证书、评级报告或招聘后台

任何 UI 文案、状态、组件或视觉隐喻，只要让产品看起来像推荐器、认证器、简历包装器、企业筛选器、评分系统或真实 RAG 系统，都应判定为越界。
