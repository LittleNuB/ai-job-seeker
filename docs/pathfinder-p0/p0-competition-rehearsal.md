## 3. 3 分钟讲稿

### 0:00 - 0:25 问题定义

各位评委好，寻径星图 P0 解决的是一个很具体的求职准备问题：传统工科背景的小 C，想在 3 个月内转向 AI 应用相关岗位，但不知道该优先投什么方向，也缺少一份能展示 AI 项目理解的材料。她对 RAG、知识库问答和 AI 工具有初步理解，但短期不适合主攻算法工程或大模型研发。

### 0:25 - 0:55 产品定位

寻径星图不是让用户泛泛地问大模型“我适合什么岗位”，而是用样例 JD 定航向，用 OpenDocuments 这样的公开参考项目供试航，再把试航过程整理成航迹表和作品集起点。它不做简历包装，不做能力认证，也不做录用概率预测。

### 0:55 - 1:35 星图推荐页

推荐页同时展示三条路径。第一条是行业 AI 应用产品助理，建议优先试航；第二条是行业 AI 解决方案助理，适合探索；第三条是算法工程 / 大模型研发，短期不建议。

这里的关键不是一个结论，而是证据链。每条路径都有 JD 证据、小 C 背景证据、OpenDocuments 证据、风险证据和下一步试航。小 C 的工程资料理解、报告整理和跨团队沟通经验，更容易连接到 AI 知识库产品里的需求拆解、问答样例、引用展示、失败兜底和验收指标。

### 1:35 - 2:20 OpenDocuments 试航页

进入试航页后，左侧是 OpenDocuments 原项目能力。OpenDocuments 是公开参考项目，公开能力包括多来源文档接入、AI 文档搜索、RAG 问答、引用来源展示，以及 Web UI / CLI / MCP 等能力。

右侧是小 C 的 6 问试航。这里必须分清归属：小 C 没有参与 OpenDocuments 开发，也不把原项目能力写成个人成果。小 C 的贡献是围绕工程企业知识库 AI 助手做场景拆解、2 周 MVP 方案、指标、风险和表达材料。

### 2:20 - 2:50 结果页

完成 6 问后，结果页生成航迹表、作品集一页纸草稿、指标表、用户流程草图、风险清单、合规表达建议、面试追问准备和 Markdown 导出。

完整 Markdown 只有在 6 问全部完成、反包装检查通过后才允许导出。第 6 问 AI 使用说明缺失时会阻断；如果出现“我开发了 OpenDocuments”这类表达，也会阻断完整 Markdown。

### 2:50 - 3:00 收束

寻径星图不是帮用户包装经历，而是让跨界求职者借真实岗位和公开项目完成一次可追溯、可解释、可继续打磨的岗位试航。

## 4. 点击路径脚本

1. 打开 `http://127.0.0.1:3000/pathfinder`。
2. 讲入口页固定 Demo 边界：1 个用户、3 条路径、1 个公开参考项目、1 个试航任务、1 种 Markdown 导出。
3. 点击“进入小 C Demo”。
4. 在 `/pathfinder/background` 讲小 C 背景、优势、短板、目标和 3 条样例 JD。
5. 点击“查看星图推荐”。
6. 在 `/pathfinder/recommendation` 讲三条路径状态和证据链。
7. 点击“开始 OpenDocuments 试航”。
8. 在 `/pathfinder/trial` 讲左侧 OpenDocuments 原项目能力和右侧小 C 试航贡献。
9. 点击“填入演示用小 C 作答，可继续编辑”。
10. 如需展示阻断，清空第 6 问，说明 AI 使用说明是反包装检查必要项，再恢复示例作答。
11. 点击“进入结果页”。
12. 在 `/pathfinder/result` 讲航迹表、作品集草稿、指标、风险、合规表达和面试追问。
13. 点击“下载 Markdown”，触发完整 `MarkdownSnapshot` 保存。
14. 讲结果状态：页面显示“已保存快照 / 已保存”，后端记录为 `exported / markdownSnapshot full + frontend`。

## 5. 每页讲解重点

| 页面 | 讲解重点 | 必须守住的边界 |
|---|---|---|
| `/pathfinder` | 固定 Demo，不是开放推荐器；输出是可追溯作品集起点 | 不做能力认证、录用预测、企业推荐或简历包装 |
| `/pathfinder/background` | 小 C 是传统工科学生，有工程资料理解和基础 AI 工具使用经验，也有算法研发和企业交付短板 | 样例 JD 仅用于 Demo 和样本趋势参考 |
| `/pathfinder/recommendation` | 三条路径同时展示；产品助理优先，解决方案助理探索，算法 / 大模型研发短期不建议 | 讲证据链，不讲评分、排名或胜任认证 |
| `/pathfinder/trial` | 左侧是 OpenDocuments 原项目能力，右侧是小 C 6 问试航 | OpenDocuments 是公开参考项目，小 C 没有参与原项目开发 |
| `/pathfinder/result` | 航迹表、作品集草稿、指标表、风险清单、合规表达、面试追问、Markdown 导出 | 结果是试航记录，不是正式简历、能力认证或官方贡献记录 |

## 6. 评委追问与回答

| 追问 | 回答 |
|---|---|
| 这和通用 LLM 问“我适合什么岗位”有什么区别？ | 通用 LLM 往往给开放式建议。寻径星图 P0 把输入锁定为小 C、样例 JD、三条路径和 OpenDocuments，输出必须带证据链、风险边界和 Markdown 追溯材料。它不是只给建议，而是完成一次可复核的岗位试航。 |
| 为什么只做小 C 一个 Demo？ | P0 的目标是验证闭环是否成立，而不是验证泛化规模。只做小 C 可以把路径判断、反包装导出、P1-A 保存和展示节奏打磨稳定。多人、多包和历史管理可以后续做，但不进入当前参赛 Demo。 |
| 为什么只选 OpenDocuments？ | OpenDocuments 对应企业资料分散、文档搜索、RAG 问答和引用来源这些场景，适合小 C 做产品试航。P0 只选一个公开参考项目，是为了避免变成多开源项目推荐器。 |
| 为什么不是直接帮用户改简历？ | 直接改简历容易把公开项目和 AI 草稿包装成个人成果。P0 反过来要求写清来源、License、原项目能力、小 C 贡献和不可声称内容，先产出可追溯材料，再由用户人工打磨表达。 |
| 怎么避免用户包装开源项目？ | 页面和 Markdown 都分开写 OpenDocuments 原项目能力与小 C 试航贡献；第 6 问要求说明 AI 如何辅助和人工筛选；正向表达“我开发了 OpenDocuments”等风险会阻断完整 Markdown。 |
| JD 样例是否代表真实市场？ | 不代表。页面和 Markdown 都写明样例 JD 只用于 P0 Demo 和当前样本趋势参考，不代表具体公司岗位要求或录用判断。它的作用是提供试航方向，不是替代真实求职调研。 |
| P1-A 为什么复用 `analysis_records` 而不新增表？ | P1-A 目标是最小化保存和回放当前试航记录，复用已有表可以降低迁移风险，验证 `TrailRecord / TrialAnswer[] / AntiPackagingCheck / MarkdownSnapshot` 契约。专用表、历史筛选和发布流可以在 P1-B 后再做。 |
| 后续如何从 Demo 走向可持续产品？ | 先扩大到更多人工策划的试航包，再做历史记录、权限、审核和正式用户体系。每一步都要继续保留来源、边界和反包装检查，不直接跳到自动推荐或评分系统。 |
| 这个产品对智联招聘场景有什么价值？ | 它可以帮助跨界求职者把“想转 AI”拆成具体岗位方向、试航任务和可解释材料，也能减少不清晰、自我包装式的求职表达。对平台价值是提升求职准备质量，而不是替企业自动筛选候选人。 |
| 如果用户不会代码，为什么还适合做这个试航？ | 这个试航的核心不是证明代码研发能力，而是理解行业资料、定义问题、设计 MVP 范围、指标和风险。不会代码的用户也可以围绕产品助理或解决方案助理岗位做场景拆解，但不能把它说成算法研发或系统开发成果。 |

## 7. 现场兜底方案

| 异常 | 兜底动作 | 解释口径 |
|---|---|---|
| 后端不可用 | 继续在前端填写 6 问，页面会显示保存失败但可继续本地试航；结果页仍可生成本地 Markdown | P1-A 后端保存是追溯增强，不是 Markdown 生成前置条件 |
| 前端刷新后状态异常 | 先回 `/pathfinder/trial`，点击“填入演示用小 C 作答，可继续编辑”；如已有后端记录则刷新后自动恢复 | 当前版本同时保留 sessionStorage 和后端记录恢复 |
| Markdown 下载失败 | 使用 Markdown 预览区，手动全选复制；必要时切换到复制按钮 | Markdown 内容由前端纯函数生成，预览区即最终内容 |
| 复制 Markdown 被浏览器权限拦截 | 改用“下载 Markdown”；若下载也受限，手动选中预览 textarea 内容 | 这是浏览器权限限制，不影响生成结果 |
| 移动端展示不稳定 | 切回桌面视口展示；移动端只作为补充验证 | 正式参赛主展示使用桌面，390px 主体无横向溢出已验证 |
| API 保存状态失败 | 继续讲本地试航和导出；页面会显示“保存失败，可继续本地试航” | 失败不影响结果生成，后续可恢复服务后重新保存 |
| 评委质疑“是不是包装项目” | 直接指向页面分区和 Markdown 的不可声称内容 | OpenDocuments 是公开参考项目；小 C 只做场景拆解、MVP、指标、风险和表达材料 |
