## 1. 使用边界

本文档只用于 P0 polish 的页面文案、演示话术和反包装表达收口。

本文档不修改 P0 Scope Lock，不新增 P1/P2 能力，不改变已锁定的 Demo 主线。

P0 仍然锁定：

- 唯一 Demo 用户：小 C
- 三条路径：
  - 行业 AI 应用产品助理：优先试航
  - 行业 AI 解决方案助理：适合探索
  - 算法工程 / 大模型研发：短期不建议
- 唯一开源项目：OpenDocuments
- 唯一任务：工程企业知识库 AI 助手试航
- 唯一导出格式：Markdown

P0 禁止出现：

- 能力认证
- offer 概率预测 / 录用概率 / 上岸概率
- 企业筛选 / 企业推荐 / 精准内推
- 简历包装 / 简历自动优化
- 多开源项目智能推荐
- 真实 RAG 检索
- 复杂评分系统
- 算法工程速成 / 大模型研发训练路径
- 暗示小 C 参与 OpenDocuments 官方贡献
- 暗示完成试航等于岗位胜任或录用优势

## 9. 现场 Q&A 最终版

状态：P0 立即可用

### Q：这是不是简历包装工具？

A：不是。P0 明确写来源、License、原项目能力、小 C 试航贡献和不可声称内容。它的目标是反包装：防止把公开项目、Demo 方案或 AI 草稿写成个人成果。

### Q：为什么不推荐算法岗？

A：小 C 当前证据更集中在工程资料理解、报告整理和产品表达。算法工程 / 大模型研发通常需要模型实验、代码实现和工程证据，所以短期不建议作为主路径。

### Q：OpenDocuments 到底是谁的贡献？

A：OpenDocuments 是公开参考项目，原项目能力来自原作者 / 维护者。小 C 不能声称参与官方贡献。小 C 的贡献只限于场景拆解、2 周 MVP、指标、风险、演示材料和作品集表达草稿。

### Q：为什么 6 问必须完整？

A：6 问覆盖项目理解、岗位连接、场景缺口、应用方案、作品延展和 AI 使用说明。缺任何一问，追溯链就不完整，尤其缺第 6 问时无法说明 AI 使用边界，所以不能导出完整 Markdown。

### Q：结果页能不能直接当正式作品集？

A：不能直接当正式作品集。结果页是一页作品集草稿和试航记录，适合后续人工整理。它必须保留来源、License、边界说明和不可声称内容。

### Q：为什么 P0 只选一个开源项目？

A：为了锁定边界，验证“路径试航 + 反包装导出”的闭环。P0 不做多开源项目智能推荐，也不做真实 RAG 检索。多试航包管理可留到 P1 / P2，但不能变成项目推荐器。

### Q：为什么不开放用户粘贴 JD？

A：P0 要验证固定 Demo 的可信闭环。开放 JD 会把重点带到泛化推荐，容易扩大范围。P0 只使用样例 JD 做路径判断展示。

### Q：Markdown 为什么必须有九项？

A：九项覆盖背景、路径、JD 说明、开源来源、原项目能力、小 C 贡献、不可声称内容、6 问作答和免责声明，能保证导出材料可追溯、可复核、不越界。
